Scoring methodology

Every score in AI Resume Checker comes from the rules on this page. Nothing is random, and no score is ever returned without a value behind it.

1 Structure Score

How readable the document's skeleton is to an automated parser.

Sub-checkWeightRule
Sections present{{ structure_weights.sections }} Core sections count 1.0 each, optional sections 0.5 each, over the 5 core + 5 optional sections.

2 Content Score

Whether the writing itself carries evidence.

Sub-checkWeightRule
Content length{{ content_weights.length }} Full marks between 300 and 800 words; shorter or longer is penalised progressively.
Action verbs{{ content_weights.action_verbs }} Distinct action verbs (developed, designed, implemented…) / 8 × 100.
Measurable results{{ content_weights.quantified }} Numbers, percentages and volumes found / 4 × 100.
Sentence readability{{ content_weights.detail_level }} Full marks when the average sentence is 25 words or fewer.
Vague phrasing{{ content_weights.filler }} Starts at 100 and loses 12 points for each occurrence of phrases such as ‘responsible for’ or ‘etc.’.

3 Skills Score

Depth and relevance of the skill vocabulary.

Sub-checkWeightRule

! Honest limitations

What this system cannot do, stated plainly.

  • The analyzer reads text only. A scanned PDF produces an error rather than a guess.
  • Only skills listed in data/skills.json can be detected. Adding an entry there extends the system with no code change.
  • Section detection depends on headings being visible as text. Resumes that place headings inside images are not parsed correctly.
  • Experience, project and education parsing is heuristic. Multi-line entries can be merged into one.
  • The ATS number is a readability estimate based on general practices, not a real ATS run.
  • No claim is made that a candidate is qualified or unqualified for any role.
